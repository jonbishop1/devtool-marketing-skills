# Integration marketing playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Verify the SDK/CLI/plugin/CI/API workflow, versions, permissions, expected result, artifact storage, secrets handling, maintenance, and support ownership. Distinguish a custom example from an officially supported partner integration.

## Task-specific method

Show where the SDK, CLI, plugin, CI action, or API fits into a real developer workflow. State who maintains the adapter and what each product is responsible for.

## Application brief

Deliver: A verified workflow brief, integration page or listing, example and evidence notes, support boundary, distribution drafts, and maintenance plan.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not generate a directory of unsupported product pairs, use restricted brand assets, or imply endorsement because an API is public.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
