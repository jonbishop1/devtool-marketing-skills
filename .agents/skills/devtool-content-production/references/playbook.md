# Content production playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

For tutorials state supported runtime, installation, sanitized input, expected result, failure recovery, and integration boundary. Test only in the authorized environment, label untested commands, and show a process diagram when it explains execution.

## Task-specific method

Use concrete inputs and outputs, a runnable path, failure cases, and links to supported interfaces. Technical readers should be able to distinguish a demonstration from production guidance.

## Worked application

For this scenario, apply the task-specific method above and deliver: A finished draft, source and verification notes, any unresolved publication blockers, and an explicit next step appropriate to the reader. Keep internal evidence notes out of public copy unless relevant.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not invent customers, quotes, benchmarks, research results, or working code. Respect source licenses and attribution; transform ideas into original task-specific work rather than paraphrasing an entire source.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
