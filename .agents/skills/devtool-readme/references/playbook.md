# Readme playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Expose task, local/hosted boundary, supported runtime, minimal verified command, expected output, license, maintenance, and support. Make the route from a sample to own-project adoption clear without inventing traction badges.

## Task-specific method

Show a developer what they can run, what it returns, what it touches, and what adopting it would require. Keep badges subordinate to the task.

## Worked application

For this scenario, apply the task-specific method above and deliver: A complete README draft or prioritized diff, command verification notes, and the route from sample success to supported adoption.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not invent badges, download counts, customers, certifications, or executable examples. Do not replace the repository license during a marketing rewrite.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
