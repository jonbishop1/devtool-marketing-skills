# Seo audit playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Inspect docs versioning, repository/package links, supported framework examples, rendered task instructions, canonical paths, and useful transitions into a runnable evaluation. Diagnose the observed rendering issue before proposing a stack rewrite.

## Task-specific method

Inspect versioned docs, repository-to-site routes, package and framework pages, and canonical paths for examples. Technical content may need to remain available even when an older version should not be the search landing page.

## Application brief

Deliver: A prioritized issue register with affected URL, observed evidence, severity rationale, proposed fix, owner or dependency, and a reproducible verification step.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not claim indexing, traffic loss, rich-result eligibility, or AI citation performance without corresponding evidence. A missing public file is not proof that a whole product is agent-incompatible.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
