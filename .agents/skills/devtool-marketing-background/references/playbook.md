# Marketing background playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Record language/runtime, local or hosted execution, package or repository access, current debugging/integration workflow, and who maintains a new dependency. Define first useful task success and repeated project use separately.

## Task-specific method

Capture supported environments, installation path, local versus hosted behavior, maintainer ownership, and what turns a successful experiment into a durable team workflow.

## Worked application

For this scenario, apply the task-specific method above and deliver: A compact brief with facts, evidence links, open questions, assumptions, the current goal, meaningful success, constraints, and the next decision. Add only material changes to an existing brief.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not default to the US, a signup conversion, a funding-based stage, or a fixed channel budget. Product age and funding do not prove product-market fit.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
