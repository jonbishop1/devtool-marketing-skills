# Content strategy playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Build around supported stacks, debugging and integration tasks, migration decisions, and production tradeoffs. Choose a canonical docs path and a distinct editorial purpose; avoid duplicating reference documentation to fill a calendar.

## Task-specific method

Cover real stack combinations, examples, debugging, migration, and production tradeoffs. Distinguish reference documentation from opinion or editorial explanation.

## Worked application

For this scenario, apply the task-specific method above and deliver: A prioritized portfolio, cluster map, production briefs, distribution plan, and maintenance responsibilities. Explain why the first items deserve the available effort.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not create programmatic pages unless each has distinct user value and reliable source data. Do not promise rankings or replace a requested new-content plan with an unsolicited refresh project.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
