# Conference pipeline playbook

## Fictional product context

TraceNest is a fictional local HTTP replay tool. An engineer can replay a sanitized fixture locally, but service integration needs a platform owner. Sample replay is not proof of recurring project value. Do not invent hosted behavior, speed improvements, or customer results.

## Decision to resolve

Use a reproducible engineering demo with a safe offline fallback. Qualify stack, recurring task, and team-integration ownership. Capture only permitted notes and an agreed next step; badge scans are not qualified pipeline or blanket outreach consent.

## Task-specific method

Use a task demo that an engineer can reproduce after the event. Qualify supported stack and the path from individual experiment to team integration.

## Completed example

Live demo depends on a local service and documented runtime. Test the full path before the event. Fallback: a labelled recording plus fixture/expected-response worksheet if network or installation fails. This is a recorded demonstration, not a claim that the product works offline. Capture an agreed evaluation task and contact preference, not inferred consent from a scan.

Do not assume missing capabilities or report proposed tests as completed. A useful answer identifies what is known, finishes the requested artifact within that scope, and names the next bounded verification when needed.

## Review criteria

Do not scrape restricted attendee data, send unapproved messages, or report every scan as pipeline. Separate preparation from paid sponsorship or outreach execution.

The [shared method examples](shared-methods.md) provide additional templates and cross-product examples; apply only those that fit the product scope.
